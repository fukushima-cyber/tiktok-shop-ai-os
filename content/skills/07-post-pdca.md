# Skill 07：自アカウント自動集計・投稿パッケージ & 48h PDCAループ

> **使うタイミング**：
> ①アカウント（`@handle`）を預かった直後の過去投稿スキャン、②ゲートC承認後の投稿準備、③投稿48時間後の自動集計＆次回企画への還流（Muse / GrokBot の定期ルーティン対応）。
> **読むファイル**：`./core/00-os-principles.md`（第3章：3段階評価軸）＋ `./scripts/account_tracker_ref.py`。
> **ゴール**：人間の手入力に頼らず、**自アカウントの公開投稿をAIが自動集計 → 48h到達分を3段階判定 → 勝ち型・撤退型を台帳に保存 → 次回企画（Skill 02）へ自動接続** する運用ループを回す。

---

## 1. アカウントを預かったときの自動運用フロー

依頼者から自分のTikTokアカウント（`@handle` またはプロフィールURL）を受け取ったら、AIは作業環境に台帳ファイル（`account_state.json` と `account_report.md`）を作り、毎回これを更新しながら運用します。

### 取得できるもの vs 非公開のもの（正直に扱う）
- **AIが自動取得できる項目**（`account_tracker_ref.py sync` / 公開API利用）：
  - 投稿一覧・動画ID・タイトル・投稿日時（JST）・尺・再生数・いいね数・コメント数・シェア数・保存数・24h/48hスナップショット・広告フラグ目安
  - ※WAFやAPI仕様変更で一時的に取得できない場合は、数字を創作せずエラーを報告し、依頼者へスクショまたはCSVの貼り付けを求める。
- **自動取得できない非公開項目**（TikTok Shop管理画面の中）：
  - **注文数（CV）・カートクリック数・GMV**
  - これは48時間レポートを出したタイミングで、AIから依頼者へ **「48h経過したこの動画の注文数だけ教えてください（0件なら0でOK）」** と1行だけ確認し、`annotate` で台帳へ記録する。

## モードA：投稿パッケージ生成（ゲートC承認後）

完成動画と一緒に以下を出力し、投稿後に動画IDと「型・仮説・変えた項目」を台帳へ記録します（投稿実行は必ず依頼者承認後）。

1. **キャプション案（2パターン）**：末尾に `#PR`、NG語・未確認の終了日/価格なし、左下ショップ誘導あり。
2. **ハッシュタグ（4〜6個）**：商品名＋悩みジャンル＋`#TikTokショップ` `#PR`。
3. **サムネイル用フレーム提案**：何の話か一目で伝わる秒数と位置。
4. **固定コメント／想定質問への返信テンプレ**：購入前の不安（持ち・使い方・肌質等）に事実ベースで返す案。
5. **台帳登録コマンド（投稿直後にAIが実行）**：
   ```bash
   python3 account_tracker_ref.py annotate --state ./account_state.json --video-id <動画ID> --pattern "Pxx x Sxx" --hypothesis "<仮説>" --changed "<変えた1項目>" --channel organic
   ```

## モードB：自アカウント自動集計 & 48h PDCA判定

アカウントの振り返り時、または新しい動画を作る直前に実行します。

```bash
python3 account_tracker_ref.py sync --handle @your_account --state ./account_state.json --report ./account_report.md
```

### 3段階ボトルネック判定マトリクス（有機48h基準）

| 判定 | 数値条件（有機・経過48h以上） | 診断 | 次の一手（次回ブリーフの方針） |
|---|---|---|---|
| **① 勝ち型（横展開）** | 再生 ≥ 1,000 **かつ**（いいね率 ≥ 0.5% **または** 保存率 ≥ 0.15% **または** 注文 ≥ 1） | 構造が当たっている | **同型で1変数だけ変えて横展開**＋Spark Ads候補として提案 |
| **② フック不足** | 再生 < 1,000 **かつ** いいね率 ≥ 0.5%（または保存率 ≥ 0.15%） | 中身は良いが冒頭で止まっていない | **型・中盤・商品パート固定**。冒頭0〜2秒だけ差し替え |
| **③ 中盤・訴求不足** | 再生 ≥ 1,000 **かつ** いいね率 < 0.5% かつ 保存率 < 0.15% かつ 注文 0 | 冒頭は止まったが中身で離脱 | **冒頭固定**。中盤テンポ(1.5s)・絵と主語・認識転換を改修 |
| **④ CV導線不足** | 再生 ≥ 1,000 かつ いいね/保存良好 だが 注文 0 | 共感止まりで今買う理由が弱い | **冒頭・中盤固定**。商品パートの情景化・理由重ね・CTA・固定コメを改修 |
| **⑤ 全面未達（撤退）** | 再生 < 1,000 かつ いいね率 < 0.5% かつ 保存率 < 0.15% かつ 注文 0 | 型×商材が噛み合っていない | **この型は撤退（二度と出さない）**。Skill 02へ戻り別系統の型へ |

※広告配信（Spark Ads）は有機判定から分離し、注文数・保存率ベースで別枠評価する。

### 次回企画（Skill 02）への自動引き継ぎ
`account_report.md` に出力された **「勝ち型」「撤退済み型」「直近使用型」** をそのまま Skill 02 の入力として渡し、以下の次回ブリーフを出力する。

```markdown
# 48h自動集計 & 次回制作ブリーフ（@アカウント名）

## 今回の実測（48h到達分）
- 動画 / 型：
- 再生：〇〇 / いいね：〇〇（〇.〇〇%） / 保存：〇〇（〇.〇〇%） / 注文：〇件（または未確認）
- 判定：【①勝ち型 / ②フック不足 / ③中盤不足 / ④CV導線不足 / ⑤撤退】

## 次回1本の自動指示書
- モード：【PDCA検証（同型で1変数変更） or 新規企画（撤退・既出型を除外）】
- 固定するもの / 変える1項目 / 次回の仮説：

👉 注文数が未確認の動画があれば件数だけ教えてください。そのまま次回企画（Skill 02）へ進めますか？
```

## モードC：Muse / GrokBot 定期ルーティン設定（自動PDCA運用）

Muse や GrokBot のスケジュール実行機能に次の1文を毎日定時（例：毎日21:00 JST）で登録しておくと、人間が催促しなくてもPDCAが自動で回ります。

```text
https://fukushima-cyber.github.io/tiktok-shop-ai-os/llms.txt を読み、Skill 07に従って私のアカウント（@ここにハンドル）を自動集計してください。48時間経過した新規動画があれば3段階PDCA判定と次回企画ブリーフを作成して報告してください。投稿や広告操作はせず報告のみにしてください。
```
